# herdr-triggers design

One Go binary, `cmd/herdr-triggers`. Packages in `internal/`:

- **task**: `tasks.json` schema and validation (unknown fields rejected, defaults `agent: claude`, `catchUpMinutes: 120`). Cron validated by gronx, exactly 5 fields.
- **schedule**: `Next` (cron in local time, once, webhook never) and `Plan` (tick: fire, missed, armed state). A run late by at most `max(60s, catchUpMinutes)` fires, so a run due during sleep fires on wake; older ones are `missed`. A once task already past when first seen fires within that window, else is `missed`.
- **agents**: argv per agent: model flag (`--model`, `-m` for codex), `agentArgs`, prompt separator (`--`, `--prompt` for opencode, nothing for unknown binaries). `CLAUDE_CONFIG_DIR` via `env` for claude only.
- **store**: paths (XDG), `tasks.json` edits under `flock` with atomic writes, SQLite `state.db` (modernc, WAL, busy timeout, immediate transactions) for `runs` and `deliveries`. `Reserve` assigns run `n` per task in one transaction.
- **config**: `config.json` `{backend: auto|app|cli, session, public}`; `auto` = app when `herdr-app` is on `PATH`.
- **dispatch**: two backends, recorded per run (`runs.backend`). **app**: `herdr-app status`; if no window, spawn `herdr-app` and poll (60 s); then `herdr-app do space.new {name, folder, argv, task}` and an `hc wait --timeout 30` loop. `message` and `timeout` reasons are check-ins; `idle` at turn 0 is startup, not the end (pause 2 s). On check-ins: `timeoutAt` passed → `hc kill`, `timeout`; `blocked` from the agent status or a confirm prompt in the screen's last 5 lines while not working. **cli**: `herdr workspace list`; if it fails, spawn `herdr server` and poll. `workspace create --cwd --label --no-focus [--env CLAUDE_CONFIG_DIR]`, then `agent start <t-id-n> --kind <agent> --pane <root> -- <model flags, agentArgs, prompt prefix, prompt>` (retried on `agent_pane_busy`). The prompt goes in argv, not `agent prompt`: `agent start` can report ready while a wrapper script is still starting the real agent, and a pasted prompt is lost. herdr rejects newlines in args, so they become `\n`. Status `starting` until `agent wait --until working|blocked`; a turn too fast to see counts when the agent is idle and its `state_change_seq` moved 2+; 15 min without work → `failed`. Then `agent wait --until done|idle|blocked` (30 s check-ins); timeout → `workspace close`.
- **app**: `Step` (tick), `Reconcile` (active runs: gone terminal or agent → `exit`, live → watched again by its backend), `Begin`/`RunNow` (overlap guard, reserve, disable once tasks, payload framing). Alerts on `failed`/`blocked`/`timeout`/`error`/`missed`.
- **webhook**: `POST /hooks/{id}` or `/hooks/{id}/{token}`, token from the path, Bearer, `X-Triggers-Token` or `?token=`, compared in constant time. Body ≤ 64 KB. Each delivery logged with its outcome (`accepted`, `unauthorized`, `too_large`, `busy`).
- **tunnel**: `config.json` `{provider, baseUrl, domain}`. `Open` starts `tailscale funnel`, `ngrok` or `cloudflared` (`--protocol http2`) and scans its output for the public URL (cloudflared: after `Registered tunnel connection`). `serve` stores the URL or the error in `state.db` `meta`, clears it on start and exit; the child gets `Pdeathsig` on Linux.
- **service**: systemd user unit or launchd agent running `herdr-triggers serve`, with `PATH`, `CLAUDE_CONFIG_DIR` and `TRIGGERS_*` copied in. `serve` records its PID in `meta` at start and clears it on exit; `status` and the TUI check that process (on Linux, that its cmdline is `serve`), wherever it runs.
- **Footprint**: idle `serve` does no disk writes: the tick (5 s) only `stat`s `tasks.json` and re-parses it when mtime or size change; next fire times are recomputed only when a task changes or fires; an invalid `tasks.json` is logged once per distinct error. SQLite uses WAL with `synchronous=NORMAL`. Each active run costs one `hc wait`/`herdr agent wait` process per 30 s.
- **daemon**: `start` writes `cli.json`, reuses the remembered `{space, terminal}` while it runs `herdr-triggers serve`, else closes it and opens a "Triggers" space. `stop`, `status`.
- **view**: `list --json` for the mod and the TUI. **tui**: Bubble Tea + Huh; one screen (table + detail panel of the selected task), `render(screenData)` is pure and tested at fixed sizes.
- Never write app layout files or `herdr.space`/`herdr.tab` labels; only documented `herdr-app do` commands and `hc` (app backend) and `herdr` CLI commands (cli backend).
- **Mod**: `mods/triggers` reads `~/.config/herdr-triggers/cli.json` and polls `list --json` / `status --json` every 10 s; actions call `run-now --bg`, `enable`, `disable`, `start`. See its `RECIPE.md`.
